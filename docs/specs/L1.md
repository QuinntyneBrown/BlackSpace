# L1 Requirements — blackspace.ca

## L1-1: Hero Section
Design a responsive hero section that instantly communicates what Black Space Canada is — headline, subheadline, and two CTAs — across phone, tablet, and desktop breakpoints. Dark space-themed aesthetic with everything above the fold.

## L1-2: Problem Section ("Why This Exists")
Design a responsive section that communicates the underrepresentation problem using short paragraphs and bold statements with supporting stats. Must feel conversational, not corporate.

## L1-3: Who It's For Section
Design a responsive audience identification section using cards or an icon grid for five audience categories (Software Engineers, Hardware Engineers, Students, Entrepreneurs, Scientists). Three-column on desktop, stacked on mobile.

## L1-4: What We Do Section
Design a responsive three-pillar section (Networking, Visibility, Pipeline) as cards or columns with icons and short descriptions. Three-column on desktop, stacked on mobile. Each pillar reflects the mission: building professional networks, creating visibility for Black Canadians already doing the work, and opening pathways for the next generation to enter and thrive in the industry.

## L1-5: Signup / Join Form
Design a responsive signup form section with 5 fields (2 required, 3 optional), a CTA button, and reassurance text. Form sits on a distinct card/panel. Include the thank-you/success state after submission.

## L1-6: About the Founder Section
Design a compact responsive founder section with photo placeholder, name, title, short bio, and LinkedIn link. Small and credibility-focused.

## L1-7: Footer
Design a minimal responsive footer with contact email, LinkedIn link, independence disclaimer, and copyright line. Dark background matching the hero.

## L1-8: Navigation & Mobile Menu
Design a sticky/fixed navigation bar with the logo/wordmark and CTA. On mobile, design a hamburger menu with section links.

## L1-9: Notifications, Alerts, Dialogs & Popups
Design all overlay UI states: form validation errors, form submission success toast, email already registered alert, cookie/privacy notice, mobile menu overlay, and a generic confirmation dialog.

# Backend API Requirements

## L1-10: .NET Solution Structure & Configuration
Create a production-grade .NET 9 solution with clean architecture: API project (ASP.NET Core Minimal API), Domain project (entities, interfaces), Infrastructure project (EF Core, email), and Tests project. Configure with proper dependency injection, logging, CORS for the Angular frontend, and environment-based configuration.

## L1-11: Member Signup API
Implement a POST /api/members endpoint that accepts signup form submissions (Full Name, Email, Role/Title, Organization, Referral Source), validates input, detects duplicate emails, persists to a SQLite database, and returns appropriate responses (201 Created, 409 Conflict for duplicates, 422 for validation errors).

## L1-12: Email Service Integration
Implement a welcome email service that sends a templated welcome email upon successful member signup. Support both a real SMTP provider and a development-mode console logger. The email includes a LinkedIn group link and next meetup details.

## L1-13: Site Content API
Implement GET endpoints to serve dynamic site content: /api/content/stats (community statistics like member count), /api/content/founder (founder info), and /api/content/referral-sources (dropdown options for the signup form). This allows the Angular frontend to fetch live data.

## L1-14: Health & Observability
Implement a GET /api/health endpoint with database connectivity checks, structured logging via Serilog, and request/response middleware for performance monitoring. Include Swagger/OpenAPI documentation for all endpoints.

## L1-15: API Integration Tests
Create comprehensive integration tests using WebApplicationFactory covering all API endpoints, validation rules, duplicate detection, error responses, and health checks. Tests use an in-memory SQLite database.
